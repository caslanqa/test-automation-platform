Mobile locators are ranked, and the ranking is not a matter of taste. The inspector scores every
candidate deterministically and reports why each one is risky; a hand-picked selector that ignores
that score is a scheduled failure.

## The order

| Strategy              | Why it is where it is                                                                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`accessibilityId`** | Put there deliberately, changes deliberately, and it is the same attribute a screen reader uses — so it is also the one a developer will not rename casually                               |
| **`resourceId`**      | Stable on Android, but platform-specific and often generated by the layout system                                                                                                          |
| **`text`**            | Readable, but it is copy: it changes with localisation and with product wording. Long text is worse than short                                                                             |
| **`index`**           | Position within a set of matches. Only ever as a disambiguator on top of an attribute, never alone                                                                                         |
| **`point`**           | Raw coordinates. **Never in a committed test.** It depends on resolution, density, orientation and layout, and it fails silently by hitting the wrong element rather than by not resolving |

## Read the warnings, not just the score

The inspector attaches reasons, and each one means something specific:

- **not unique** — several elements match. The selector will resolve to whichever the driver returns
  first, which is not a contract. Add a disambiguator or find a better attribute.
- **position-dependent** — an index was pinned. Reordering or filtering the list changes what this
  resolves to. Acceptable for a genuinely ordered list, wrong for a search result.
- **outside the app under test** — the element belongs to another app or to system UI. This cannot
  resolve on replay at all; it is the heaviest penalty for a reason.
- **long text — may be dynamic or localised** — a full sentence as a selector. It will break on the
  first copy change, and on every non-default locale.

## Recording rather than guessing

`npx mobile-inspect` connects to a booted device, shows the live hierarchy, and offers the ranked
candidates for any element you pick, with the generated code. Use it instead of reading a hierarchy
dump by eye — the uniqueness check it performs against the whole tree is the part a human skips.

## Repairing a broken selector

When a mobile test fails to find an element, establish which of these it is before changing anything:

1. **The element is not on screen yet.** A missing wait, an animation, or the flow did not get there.
   Changing the selector will not help, and a coordinate "fix" will make it worse.
2. **The element is on screen and the selector no longer matches it.** This is the repairable case —
   and the replacement must be provably the same element: same role or class, same accessible name,
   inside the same container, and unique. Two independent signals, not one.
3. **The element is genuinely gone.** That is a product change. Report it; do not re-point the test at
   whatever is nearest.

Never repair a selector by falling back to coordinates. It converts a loud failure into a test that
passes while tapping the wrong thing, which is worse than the failure it replaced.
